## D-27(1) — Settings round-trip

**Goal:** Slider value persists through driver via PUT /settings; survives client restart via driver Init read-back.

**Steps:**

5. Open %APPDATA%\MicMap\config.json; confirm `"sensitivity": 0.42`.
6. Close micmap.exe; restart it.

## D-27(2) — Validation rejection

**Goal:** Out-of-range PUT returns structured 400; driver state unchanged.

**Steps:**
1. With micmap.exe + driver running (sensitivity at 0.42 from D-27(1)), open a separate command prompt.
2. Run:
   ```
   curl -X PUT -H "Content-Type: application/json" -d "{\"version\":1,\"detection\":{\"sensitivity\":-1.0,\"minDurationMs\":300,\"cooldownMs\":300,\"fftSize\":2048},\"audio\":{\"deviceNamePattern\":\"Beyond\",\"bufferSizeMs\":10},\"steamvr\":{\"dashboardClickEnabled\":true},\"training\":{\"dataFile\":\"training_data.bin\"}}" http://127.0.0.1:27015/settings
   ```
3. Confirm response: HTTP 400 + body containing `"field":"detection.sensitivity"` and `"reason":"must be in [0.0, 1.0]; got -1.000000"`.
4. Run `curl http://127.0.0.1:27015/settings`; confirm sensitivity unchanged (still 0.42 from D-27(1) — no partial mutation).

**Result:** [PASS / FAIL]
**Evidence:** [paste curl output verbatim]

## D-27(3) — Driver-down UX

**Goal:** Stopping SteamVR flips the indicator to red within 1 health-poll cycle; settings disable; restart re-enables.

**Steps:**
1. With client running and indicator green, stop SteamVR (Steam → SteamVR icon → Quit).
2. Within 1-2 seconds (1 Hz health poll), confirm Driver-loaded indicator turns orange/red ("● Driver: Not loaded — install or enable in SteamVR").
3. Confirm SteamVR-running indicator also flips.
4. Hover any settings slider; tooltip "Driver not loaded — settings cannot be changed" appears; slider grayed out.
5. Restart SteamVR. Within 1-2 seconds the indicator flips back to green; sliders re-enable.

**Result:** [PASS / FAIL]
**Evidence:** [screenshot of red-indicator state + green after restart]

## D-28 — 100-PUT stress

**Goal:** No driver crash, no leaked file handles, config.json integrity preserved under tight-loop PUT.

**Steps:**
1. With driver running, in command prompt:
   ```
   for /L %i in (1,1,100) do (
     curl -s -X PUT -H "Content-Type: application/json" ^
       -d "{\"version\":1,\"detection\":{\"sensitivity\":0.5,\"minDurationMs\":300,\"cooldownMs\":300,\"fftSize\":2048},\"audio\":{\"deviceNamePattern\":\"Beyond\",\"bufferSizeMs\":10},\"steamvr\":{\"dashboardClickEnabled\":true},\"training\":{\"dataFile\":\"training_data.bin\"}}" ^
       http://127.0.0.1:27015/settings
   )
   ```
2. While the loop runs, observe Process Explorer (or Task Manager → Details → vrserver.exe → Handles column). Note the handle count BEFORE the loop and AFTER (should be stable, delta < 10).
3. After loop completes, run `curl http://127.0.0.1:27015/settings`; confirm response parses cleanly.
4. Open `%APPDATA%\MicMap\config.json`; confirm valid JSON (no torn write, no partial replacement).

**Result:** [PASS / FAIL]
**Evidence:** [handle count before/after + final config.json content]
