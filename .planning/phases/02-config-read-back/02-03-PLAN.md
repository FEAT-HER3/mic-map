    1. Build the app:
       ```
       cmake --build build --target mic_map --config Debug
       ```
       Expected: exit 0, produces `build\apps\micmap\Debug\mic_map.exe` (or whatever the configured output path is — the artifact name is `mic_map` per CMakeLists; some scripts may alias it `micmap.exe`).

    2. Capture the BEFORE state of the config file:
       ```
       cat "$APPDATA/MicMap/config.json" 2>/dev/null || echo "NO CONFIG YET (first run)"
       ```
       Note what's there (or "NO CONFIG YET").

    3. Launch the app:
       ```
       ./build/apps/micmap/Debug/mic_map.exe
       ```
       (If the binary is at a different path on your machine, find it: `find build -name 'mic_map.exe' -o -name 'micmap.exe'`.)

    4. In the app UI:
       - Pick a microphone device that is NOT the default (any non-default `Beyond` match — even if it's just a different USB mic).
       - Change the **detection sensitivity** slider to something distinctive, e.g. exactly `0.42` or `0.85` (record the exact value).
       - Change the **detection duration (ms)** to a distinctive value, e.g. `450` or `750` (record the exact value).
       - Change the SteamVR `dashboardClickEnabled` toggle from its default `true` to `false`.

    5. Quit the app via its normal exit path (close window / File → Exit / etc. — do NOT kill the process; the saveDefault() call must run on graceful shutdown). The MICMAP shutdown log should print `Saved config to: ...config.json` to wherever logs go (stderr / app log file).

    6. Confirm the file was atomically written and contains your changes:
       ```
       cat "$APPDATA/MicMap/config.json"
       ```
       Expected: a JSON object with `"sensitivity": 0.42` (or whatever you set), `"minDurationMs": 450`, `"dashboardClickEnabled": false`, and your selected `"deviceNamePattern"` / `"deviceId"`. The numeric values match what you typed; the dashboard flag matches what you toggled. If the file shows defaults instead, the save path didn't persist — Plan 02 has a bug.

    7. Confirm there is NO `config.json.tmp` left behind (atomic swap completed cleanly):
       ```
       ls "$APPDATA/MicMap/" | grep '\.tmp$' && echo "FAIL: tmp file left behind" || echo "OK: no tmp leftover"
       ```
       Expected: `OK: no tmp leftover`.

    8. Relaunch the app:
       ```
       ./build/apps/micmap/Debug/mic_map.exe
       ```

    9. In the relaunched UI:
       - The selected microphone device matches what you picked in step 4.
       - The detection sensitivity slider shows `0.42` (or your exact value).
       - The detection duration shows `450` (or your exact value).
       - The SteamVR `dashboardClickEnabled` toggle is `false`.

    10. Quit the app again (graceful exit).

    11. Optional sanity check — induce a corruption to validate CFG-02 manually:
        ```
        # While app is closed:
        echo '{ "audio": { "bufferSizeMs": 25, },  trailing comma!' > "$APPDATA/MicMap/config.json"
        ./build/apps/micmap/Debug/mic_map.exe
        ```
        Expected: app launches without crashing. After a few seconds, quit. Then:
        ```
        ls "$APPDATA/MicMap/" | grep 'corrupted'
        ```
        Expected: at least one `config.json.corrupted.YYYYMMDD-HHMMSS` file exists; the live `config.json` has been replaced with defaults serialized by the new writer (you can `cat` it to confirm valid JSON with default values).

    **PASS** = steps 1-9 succeed exactly as described. The optional step 11 is a bonus validation; failure of step 11 alone is a soft fail (log and document — but the phase can still close on automated T-2 having passed).

    **FAIL** = any of:
    - The relaunched UI shows defaults instead of your changes (CFG-01 + CFG-05 violated — the data is being read but not displayed, OR not being read, OR not being saved).
    - `config.json.tmp` is left behind after a normal save (atomic-write incomplete).
    - The app crashes on launch with a corrupted config in step 11 (CFG-02 violated — Plan 02's defensive parser isn't triggering).
    - The file in `%APPDATA%\MicMap\config.json` after step 5 is empty, malformed, or contains the OLD pre-step-4 values (save path broken).

    On FAIL: capture the exact failure mode, the contents of `%APPDATA%\MicMap\config.json` at the failure point, and any stderr/log output from the app. Do NOT mark the checkpoint approved — return a description of what went wrong.
