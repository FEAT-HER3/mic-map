## D-25(6): Coexistence handshake / Pitfall 10

### Setup
1. `default.vrsettings`: BOTH flags ON.

2. Restart SteamVR (keep `micmap.exe` client running).
3. After SteamVR re-boot: `curl -s http://127.0.0.1:27015/health | jq .driver_detection_active` should now return `false`.
4. Wait ≥ 1 second (the DriverClient cache TTL).
5. Cover the mic.
6. Observe: SteamVR dashboard toggles via the CLIENT trigger path (v1.5 POST /button — verify by `grep "POST /button" vrserver.txt` shows fresh entries).

### Pass criteria
- Single dashboard toggle per mic-cover when both flags ON (no double-tap).
- `curl` confirms `driver_detection_active=true` when both flags ON.
- After mid-session flag-OFF + driver restart, `curl` confirms `driver_detection_active=false`.
- After mid-session flip, micmap.exe client logs contain `onTrigger: driver_detection_active=true, suppressing` BEFORE the flip and stop containing it AFTER (within the 1s cache TTL window).
- After mid-session flip, vrserver.txt shows `POST /button` traffic resuming (client trigger path is alive again).

### Evidence
- curl output (both states): `…/d25-6-health-flag-on.json`, `…/d25-6-health-flag-off.json`.
