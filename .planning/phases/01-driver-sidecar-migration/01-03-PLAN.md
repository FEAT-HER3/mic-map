### Driver target new wire contract (consumed by app-side from Plan 02 Task 2)

```
POST /button HTTP/1.1
Host: 127.0.0.1:<port>
Content-Type: application/json   (optional — body is parsed regardless)

{"state":"down"}    →  200  {"status":"ok"}   + push PressCommand{Down}
{"state":"up"}      →  200  {"status":"ok"}   + push PressCommand{Up}
<bad JSON>          →  400  {"error":"malformed JSON body"}                      (no push)
missing state       →  400  {"error":"missing \"state\" field"}                  (no push)
other state         →  400  {"error":"state must be \"down\" or \"up\""}         (no push)
```

    - `Init(IVRDriverContext*)`: calls `VR_INIT_SERVER_DRIVER_CONTEXT(pDriverContext)`, emits `DriverLog("MicMap driver initializing (sidecar mode)\n")`, constructs `commandQueue_ = std::make_unique<CommandQueue>()`, constructs `httpServer_ = std::make_unique<HttpServer>(*commandQueue_)`, calls `httpServer_->Start()` and returns `VRInitError_Driver_Failed` on failure, returns `VRInitError_None` on success.     - `Cleanup()`: stops HTTP server, releases CommandQueue, clears init-logged and awaiting-HMD latches (safe to re-init).
    - `RunFrame()`:
      - First call emits `DriverLog("MicMap driver v%s built %s %s - RunFrame starting\n", MICMAP_DRIVER_VERSION, __DATE__, __TIME__)` exactly once (SVR-10).
      - Drains ALL OpenVR events via `vr::VRServerDriverHost()->PollNextEvent(&ev, sizeof(ev))`. For `ev.eventType == VREvent_TrackedDeviceDeactivated && ev.trackedDeviceIndex == k_unTrackedDeviceIndex_Hmd`: sets `hSystemClick_ = k_ulInvalidInputComponentHandle`, sets `state_ = HmdComponentState::Invalidated`, emits `DriverLog("MicMap: HMD deactivated, handle invalidated\n")`.
      - If `state_ != Ready`: calls `TrackedDeviceToPropertyContainer(k_unTrackedDeviceIndex_Hmd)`. On invalid return (== `k_ulInvalidPropertyContainer`): if `!loggedAwaitingHmd_` emit `DriverLog("MicMap: awaiting HMD container\n")` and set `loggedAwaitingHmd_ = true`; skip the rest. On valid return: call `CreateBooleanComponent(container, "/input/system/click", &hSystemClick_)`; on `VRInputError_None` set `state_ = Ready`, emit `DriverLog("MicMap: /input/system/click created (handle=%llu)\n", hSystemClick_)` once; on failure set `hSystemClick_ = k_ulInvalidInputComponentHandle` and `DriverLog("MicMap: CreateBooleanComponent failed: %s (%d)\n", VRInputErrorName(err), (int)err)`.
      - Drains `CommandQueue` via `try_pop()` in a `while` loop (non-blocking, no OpenVR call under the lock). For each command:
        - `Down` kind: if `state_ == Ready`, stamps `pressTimestamp_ = steady_clock::now()`, clears `pendingReleaseAt_` if set, calls `UpdateBooleanComponent(hSystemClick_, true, 0.0)`. On error: log via `VRInputErrorName`, flip to Invalidated per Pitfall 1. If `state_ != Ready`: emit `DriverLog("MicMap: dropped press command (handle invalid)\n")` (D-09, one per drop).
        - `Up` kind: if `state_ == Ready`, compute `elapsed = steady_clock::now() - pressTimestamp_`. If `elapsed >= kMinHold (100ms)`: call `UpdateBooleanComponent(hSystemClick_, false, 0.0)` immediately (with error-handling as above). Else: set `pendingReleaseAt_ = pressTimestamp_ + kMinHold`. If `state_ != Ready`: emit D-09 drop log.
      - After drain: if `pendingReleaseAt_` is set and `steady_clock::now() >= *pendingReleaseAt_`: call `UpdateBooleanComponent(hSystemClick_, false, 0.0)`, clear `pendingReleaseAt_`. Error-handled as above.
      - Max-hold watchdog (SVR-06 + Open Question 5): if the button is currently held down (track via `isPressed_` flag or last-written value) AND `steady_clock::now() - pressTimestamp_ > kMaxHold (5s)`: force `UpdateBooleanComponent(false)`, clear state, emit `DriverLog("MicMap: max-hold watchdog fired (no UP received in 5s)\n")`.
    - Handle valid+value tracking: avoid redundant `UpdateBooleanComponent` on every RunFrame — only call on transitions (Pitfall 12 anti-pattern). Track `lastWrittenValue_` bool; only call Update when the command kind would change it.
