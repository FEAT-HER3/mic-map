### driver/src/command_queue.hpp (target content)

```cpp
#pragma once
#include <deque>
#include <mutex>
#include <optional>

namespace micmap::driver {

struct PressCommand {
    enum class Kind { Down, Up };
    Kind kind;
};

class CommandQueue {
public:
    static constexpr size_t kMaxDepth = 8;

    // Producer (HTTP thread). Returns true if queue was full and oldest dropped.
    bool push(PressCommand cmd) {
        std::lock_guard<std::mutex> lk(m_);
        bool dropped = false;
        if (q_.size() >= kMaxDepth) { q_.pop_front(); dropped = true; }
        q_.push_back(cmd);
        return dropped;
    }

    // Consumer (RunFrame). Never blocks.
    std::optional<PressCommand> try_pop() {
        std::lock_guard<std::mutex> lk(m_);
        if (q_.empty()) return std::nullopt;
        auto c = q_.front();
        q_.pop_front();
        return c;
    }

private:
    std::mutex m_;
    std::deque<PressCommand> q_;
};

} // namespace micmap::driver
```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP thread ↔ RunFrame thread | The `CommandQueue` is the only legal shared-state primitive between them. Both threads live inside the driver DLL (same process, same trust domain); the threat is data corruption / race, not authentication. |
| Test harness ↔ production code | `tests/test_command_queue.cpp` includes `driver/src/command_queue.hpp` via include-path injection. No code is compiled into the test that shouldn't be — pure stdlib. No secret or sensitive path exposed. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | `CommandQueue::push`/`try_pop` race under concurrent access | mitigate | `std::mutex` + `std::lock_guard` guards the full critical section on both producer and consumer paths (Task 1 acceptance criterion greps for `std::lock_guard<std::mutex>`). Unit test in Task 2 exercises single-thread functional correctness; cross-thread correctness is enforced by the `std::mutex` contract (UB-free under the C++17 memory model). |
| T-01-02 | Denial of Service | Unbounded queue growth under HTTP flood | mitigate | Fixed-size bound `kMaxDepth = 8` with drop-oldest overflow (grep-asserted + runtime-asserted by `test_drop_oldest_on_overflow`). Worst-case memory = `8 * sizeof(PressCommand)` ≈ 16 bytes — negligible. |
| T-01-03 | Information Disclosure | `VRInputErrorName` leaks internal SDK enum structure via log strings | accept | Log strings are written to `vrserver.txt` which is local-only (no network exfil). Enum names are public SDK symbols per `openvr_driver.h`; disclosing them in logs is not a confidentiality concern. ASVS L1 does not require mitigation. |
| T-01-04 | Elevation of Privilege | Test harness linked against driver DLL surface area | accept | `test_command_queue` does NOT link the driver DLL — it includes a header-only stdlib primitive. Zero driver privileges exposed to the test runner. Acceptance criterion explicitly forbids OpenVR linkage. |

No HIGH severity threats. All T-01-* items are either mitigated by language/construct (mutex) or accepted with rationale.
